01 · Local inference

Speed is bytes per token

To write one token, a model reads all of its weights once. So the top speed is the memory bandwidth where the weights live, divided by their size. Drag the size to see why anything that spills out of VRAM crawls.

top speed (tok/s) ≈ memory bandwidth ÷ size of the weights
Top writing speed by where the weights are read from
Tokens per second, log scale. Bandwidths: VRAM 896 GB/s (spec), RAM ~75 GB/s, NVMe 1.2 GB/s (measured).
A 4-bit KV cache: 1.8× the context for free
Qwen3.8-27B on a 16 GB card. Same writing speed (50.8 tok/s), same memory, 12 of 12 hidden facts recalled at 30K tokens.
Adopted

One formula explains four things: why 4-bit weights are fast, why speculative decoding helps, why batching raises throughput, and why "70B on a 4 GB card" tools take seconds per token.

01 · Speculative decoding

Guess a few tokens ahead, check them in one pass

The output is identical to what the big model would write; only the speed changes. Theory says deeper drafting always wins. On a full card it didn't.

Theory: tokens per pass as guesses get better
E = (1 − α^(k+1)) ÷ (1 − α), where α is how often a guess is accepted and k is how far ahead it guesses.
Measured acceptance for the adopted setting: reasoning 0.97, prose 0.87, code 0.85.
Measured: writing speed by drafting setup
Tokens per second through the real server, Qwen3.8-27B, 4-bit KV cache.
TestedAdopted
Finding: 2-ahead was accepted 83–96 % of the time, yet ran slower at 36K context than no drafting did for prose. With ~0.6 GB of VRAM spare, each pass cost more. On a full card, prefer 1-ahead.
03 · Agents and harnesses

Check against evidence; don't just think longer

Run the answer on the problem's own examples, feed back the failures, repair, keep the best. The pipeline without thinking beat plain thinking, in much less time.

A checker helps where the mistakes are

The Rust compiler fixed all 10 compile failures and broke nothing. Type-checking Python found nothing, because a strong model's wrong Python is logic, not types.

"If it compiles, it works" is false

The 15 Rust answers still failing all compiled and gave wrong answers. Tests remain the real proof.

Reusable, checked scripts beat more agents

A toolbox of saved, self-checked scripts did the same job with 1 tool call instead of 4–5, about twice as fast. A first result, not a benchmark.

06 · Self-improvement and training

Teaching a 1.7B phone brain from a bigger teacher

Ruby's on-phone model, scored on a fixed exam. A longer prompt made it act when it shouldn't. Distillation fixed both, with a third of the prompt. These rounds end at v4b; v5 has been her brain since 20 Nov.

Aim the new data at the misses

288 extra examples aimed at v1's mistakes lifted actions from 70 to 92 % and facts from 40 to 87 %.

Re-run the old exam after adding a skill

A version that learned 6 new actions started setting alarms for "What time does Fractal go to sleep?". Only the old exam showed it.

Measure the product's path

The stock model added a random action to 94 % of ordinary replies. A strict test parser had hidden it; the app's own parser exposed it.

07 · Voice

The voice is the slow part

A spoken reply took about 27 seconds to first sound, and about three quarters of that (77 %) was text-to-speech. Streaming every stage at once is what gets a reply under a second.

For reviewers

Don't take our word for it: check the proof

Every number on these slides has a source you can open, and every section of every file ends with how it was done and the files that prove it. Paths were checked on disk when this page was built.

How to review a finding
  1. On any slide, press How we know this: each number, its record and section, its result files, and a command to re-check it.
  2. Open the file's section in the library: it ends with How we did it, Proof or How we know, and The idea behind it.
  3. Run the "check it yourself" command. Most re-grade saved answers in seconds, with no model and no GPU.
  4. Look for Not kept: what was never saved is said, not hidden.
